## Task 2 — room-ready notification

`describeRoomAssignment` in `prototype-model.ts` models
`pending → assigned → ready`, but **nothing advances a stay to `ready` except
the guest arriving.** The valuable moment — "your room is ready, come up" —
does not exist. The prototype has no push/notification story at all, so this
needs a design decision before code: get approval on how a notification
surfaces (in-app banner? a stay-screen state change? a simulated push?) before
building.

Read the room-assignment spec's decision log first. In particular
`reportsRoomReadiness` exists because parts of the estate run legacy on-prem
PMSs that report an allocated room but no housekeeping status — a notification
design that assumes every property can signal readiness will strand those
stays. That flag is an **unverified assumption**; flag it to the human rather
than building more on top of it.

## Traps that will cost you hours

Learned the hard way in the previous session. All are real, all are in this
codebase or its environment.

- **The standalone CSS `translate` property is a no-op in the in-app preview
  browser.** The declaration lands in the DOM and computes to `0%`. Use
  `transform: translateX()`. A sliding carousel silently did not move while its
  indicators advanced.
- **Stale `.next/types/*.d 2.ts` duplicates fail the typecheck** with TS6053 /
  TS2300. Fix: `rm -rf .next tsconfig.tsbuildinfo`. They regenerate; expect to
  do this more than once.
- **React Compiler rules are errors, not warnings.** No `setState` in an effect
  body, no ref writes during render. Put `setState` inside a timer callback
  (see `src/lib/hooks/use-debounce.ts`) or use `useSyncExternalStore` (see
  `use-prefers-reduced-motion.ts`).
- **jsdom implements no `matchMedia`.** Already shimmed in `vitest.setup.ts`;
  do not remove it.
- **Grid tracks need `min-width: 0`.** A grid item's automatic minimum is its
  min-content width, so a sliding track of full-width panels sizes to N× the
  column instead of one.
- **Vitest resolves a PNG `import` to a bare URL string**, so `next/image`
  would then demand explicit dimensions and the suite breaks. Use `public/`
  paths plus intrinsic sizes — see
  `src/components/features/guest-app/illustrations.ts`.
- **Adding a screen breaks two tests predictably.** `SCREENS` length and unique
  id count are asserted in `prototype-model.test.ts`, and the nav-destination
  count in `guest-app-prototype.test.tsx`. Update them deliberately.
- **English plurals are not derivable.** `"Ferries".replace(/s$/, '')` gives
  `"ferrie"`. `TravelCategory.singular` is declared for this reason.
- **The Browser pane is often hidden**, and clicks, drags, scrolls and hovers
  time out when it is. Drive the app with `javascript_tool` and assert on
  measured numbers (`getBoundingClientRect`, `getComputedStyle`) instead of
  eyeballing screenshots — screenshots taken while hidden can catch a
  mid-transition frame and look like a bug that is not there.
- **`sharp` is available** for image work, but a script outside the repo cannot
  resolve it; import it by absolute path from
  `node_modules/sharp/dist/index.cjs`. To drop a flat background from line art,
  **flood-fill from the image borders, not a global colour key** — the artwork's
  fills are the same colour as the backdrop, and a key hollows them out.

## Design rules the review will reject you for breaking

From `DESIGN.md` and the codebase's own comments:

- **Pink is never decoration.** Three jobs only: the primary action, the
  current selection, live state/progress. Selection is the accent *fill* with
  ink on top — white on that pink fails contrast.
- **One inverted surface per screen**, reserved for the folio total.
- **A surface takes a hairline or a shadow, never both.**
- **Repeated list rows take a bare glyph, not a tinted chip.** The box stays
  for optical alignment, the fill goes. `.guest-entry-card` is the deliberate
  exception — three cards where the illustration is the differentiator — and it
  was peeled out of the shared row rules so it cannot leak into the nine plain
  rows.
- **Non-interactive `.guest-list-row` elements must carry `.is-static`**, which
  excludes them from the hover treatment. The hover rule matches by class, not
  by element, so a `<div>` row otherwise lights up on hover.
- Every interactive element clears a 44px target.
