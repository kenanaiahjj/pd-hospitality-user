## Design specificity verdict

The guest app’s welcome screen feels hotel-specific and visually composed for Cabana. The `/components` gallery weakens that identity: it describes a pink palette, recommends ink on that pink, and presents finance examples under a Cabana preview. `DESIGN.md` specifies plum, white surfaces, and white text on plum. The live gallery tokens are wired to plum and white, so this is a content/specification mismatch; no rendered contrast failure was confirmed.

The detector returned 359 source matches (355 advisory and 4 warning). Most are raw color or radius values. Manual review found many intentional uses for photo scrims, reward artwork, map markers, and small geometric details. These totals are scan signals, not 359 confirmed defects. One width-transition warning applies to a 6px progress indicator and has low practical impact.

## Priority issues

### [P1] Custom dialogs do not contain keyboard focus

**Location:** `src/components/features/guest-app/promoted/feed-sheets.tsx:49-54`; `src/components/ui/source-overlays.tsx:23-38, 50-67`.

**Impact:** `BrowseSheet` exposes `aria-modal="true"` but has no focus setup, Escape handling, or focus containment. `SourceDialogFrame` focuses/restores and handles Escape, but does not contain focus or make background content inert. Keyboard users can move into content that the dialog claims is modal.

**Fix:** Add initial focus, Tab/Shift+Tab containment, background inertness, Escape behavior, and focus restoration consistently; verify with keyboard navigation. Browser keyboard behavior was not testable in this run, so this is a source-verified implementation gap rather than a reproduced interaction failure.

**Suggested command:** `$impeccable harden`.

### [P2] The component gallery overflows on a phone viewport

**Location:** `src/app/globals.css:1277-1281`.

**Impact:** At 390px wide, the document measures 414px; the gallery hero content extends 24px past the viewport. This introduces horizontal page scrolling and can clip or shift content while users browse the component examples.

**Fix:** Constrain the hero grid and preview to the available column width, including `min-width: 0` and a responsive max-width for the preview.

**Suggested command:** `$impeccable layout`.

### [P2] The gallery teaches the wrong Cabana palette and product language

**Location:** `src/components/features/design-system/design-system-gallery.tsx:186, 271-272, 326-328, 337, 354-356, 391-392`.

**Impact:** Designers and engineers using `/components` see guidance that conflicts with `DESIGN.md` and examples for cashback, bank transfers, cards, and wallets. That can misdirect implementation and review even though the current primary action still renders with plum and white.

**Fix:** Replace the pink/ink-on-pink copy with the plum/white rules, then use room, arrival, hotel service, and folio examples throughout the preview and specimens.

**Suggested command:** `$impeccable clarify`.

### [P2] An unmatched booking reference can look successfully connected

**Location:** `src/components/features/guest-app/guest-app-prototype.tsx:2834-2846`; `src/components/features/guest-app/prototype-model.ts:1211-1234`.

**Impact:** The prototype accepts any typed reference by default and builds a simulated booking from it. A guest or study participant can mistake this for a real match, which weakens trust in the highest-stakes part of the entry journey. This is intentional demo behavior, not a production API failure.

**Fix:** Make strict matching the default for guest-facing demonstrations, or label the result as simulated and provide a visible sample reference.

**Suggested command:** `$impeccable clarify`.

### [P3] Shared generic controls miss the gallery’s 44px target claim

**Location:** `src/components/ui/button.tsx:19-22`; `src/components/ui/Input.tsx:10-14`; gallery claim at `src/components/features/design-system/design-system-gallery.tsx:186`.

**Impact:** Generic buttons render at 32px or 40px high and inputs at 40px, despite the gallery saying every control meets a 44px target. This mismatch applies mainly to generic UI and dashboard components; the guest app’s primary buttons have separate 44px styling.

**Fix:** Align generic control sizes with the stated target, or narrow the gallery claim to the controls that meet it.

**Suggested command:** `$impeccable harden`.

## Browser findings that need a normal-browser retest

- **Entry and gallery actions:** “Continue as guest” and “Open sheet” did not change state in the CUA session. Apple/Google buttons and other React controls behaved the same way, while ordinary link navigation worked. Because the browser harness had read-only page evaluation and could not complete its mutation preflight, this is not counted as a confirmed app bug. If it reproduces in a normal browser, entry is blocked.
- **Dashboard client panel:** `/dashboard` showed its server-rendered users, while the client panel stayed on “Loading users…”. The browser blocked direct access to `/api/users` with `ERR_BLOCKED_BY_CLIENT`; shell `curl` to that API returned HTTP 200. The cause is unresolved, so this is a preview concern, not a confirmed app defect.
- **Interrupted swipe:** `src/components/features/guest-app/stay-home.tsx:62-67` clears swipe state on pointer up but has no `pointercancel` cleanup. Touch synthesis was unavailable, so the stuck-gesture risk needs a device-level check.

## What works well

- The welcome page has a clear Cabana identity, hotel imagery, and three understandable entry choices.
- The stay model keeps room verification attached to a booking and gates in-property services until room verification. The “I can’t scan” path requests front-desk help instead of bypassing that gate.
- The source has broad focus-visible and reduced-motion coverage, and uses Next/Image for most app imagery.

## Persona red flags

- **First-time guest:** an invalid reference can appear to connect successfully; entry buttons also need a normal-browser interaction retest.
- **Keyboard user in a dialog:** focus can leave a custom modal while its accessibility semantics say the background is unavailable.
- **Phone user or gallery reviewer:** horizontal overflow affects the component gallery at 390px; finance examples and wrong palette guidance can mislead design decisions.
